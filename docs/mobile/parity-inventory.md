# React Native parity inventory

This inventory compares the web/mobile behavior at baseline commit `c11f6500cb0b79d652d0164dc06c5fd81624bf0f` with the React Native foundation on iOS and Android. The web column is based on repository source and README claims; it is not a substitute for device acceptance evidence. Each row names an owner unit and its evidence paths.

Status labels:

- **Verified (source):** the baseline source or documented product surface was found.
- **Documentation-only:** a README or guide claims the behavior, but implementation evidence was not found during this inventory pass.
- **Unresolved:** baseline behavior or acceptance remains to be established.
- **U1 shell only:** the native app starts on that platform, but feature parity work is still pending.

## U1 evidence and release gate

- `apps/mobile/src/app/index.tsx` is the initial native route; `apps/mobile/src/app/_layout.tsx` provides Expo Router and an error boundary.
- `apps/mobile/src/app-shell/AppShellScreen.tsx` renders server-selection, loading, offline/retry, and error states with light/dark palettes and existing English/Simplified Chinese message resources.
- `apps/mobile/__tests__/app-shell.test.tsx` covers those deterministic shell states and asserts no browser placeholder is rendered. The U1 route source contains only the native shell; product routes are still pending.
- `apps/mobile/app.config.ts` preserves `com.vaehor.mobile` and `vaehor` on both platform configs.
- Every feature row remains open for iOS and Android until the owning unit adds implementation and evidence. Store submission is blocked until parity rows and signed artifact/reviewer gates in [`artifact-release.md`](./artifact-release.md) are closed.
